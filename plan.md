# ================================================== 15. LEMON SQUEEZY IMPLEMENTATION

Use Lemon Squeezy's Checkout API and checkout overlay.

IMPORTANT SECURITY RULE:

NEVER expose the Lemon Squeezy API key in client-side code.

The API key must exist only on the server.

Create a server-side Next.js API route:

POST /api/checkout

The frontend sends:

{
"plan": "1-year"
}

or

{
"plan": "2-year"
}

The API route maps the plan to the correct Lemon Squeezy variant ID.

The server sends a POST request to:

https://api.lemonsqueezy.com/v1/checkouts

Use the proper JSON:API request structure.

Create the checkout with:

- store relationship
- variant relationship
- checkout_options.embed = true
- checkout customization matching the site's design
- product options
- redirect URL
- custom checkout data when useful

Return the checkout URL to the browser.

Then use Lemon.js on the frontend to open the checkout as an overlay.

The desired behavior:

User clicks:
"BUY 1 YEAR"

Frontend:
POST /api/checkout

Server:
creates Lemon Squeezy checkout

Response:
checkout URL

Frontend:
opens Lemon Squeezy checkout overlay

User:
completes payment

The user should remain visually within the landing page while the checkout opens as an overlay.

Lemon Squeezy supports this checkout overlay flow through Lemon.js and its API checkout `embed` option. Follow the current official implementation pattern.

Do not create a fake payment form.

Do not collect card numbers yourself.

Do not send payment information through our own server.

Lemon Squeezy must handle the actual payment UI.
